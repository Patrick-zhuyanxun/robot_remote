First time · Install

Install everything on a new workstation

Go through the steps in order. Tick each one when its check passes; your ticks are remembered in this browser.

    Check the hardware and OS

    • Ubuntu 22.04 (ROS 2 Humble needs it).
    • NVIDIA RTX GPU with driver 580 or newer. Tested on an RTX A5000 with 580.126.
    • About 40 GB free disk: Isaac Sim takes about 20 GB unzipped, the Python environments about 10 GB.
    • A Wi-Fi network that the Quest and the workstation both join. The workstation may be wired to the same router.
    • A Meta Quest 3 or 3S with both controllers.
    lsb_release -ds; nvidia-smi --query-gpu=name,driver_version --format=csv,noheader; df -h ~ | tail -1

    Pass: Ubuntu 22.04.x, your GPU with driver ≥ 580, and ≥ 40G available.

    Install ROS 2 Humble and the MoveIt extras

    Follow the official guide to add the ROS 2 apt repository and install ros-humble-desktop: docs.ros.org · Humble · Ubuntu (deb packages). Then add the build tools and the packages the igus MoveIt config uses:

    sudo apt update && sudo apt install -y ros-humble-desktop ros-humble-xacro \
  python3-colcon-common-extensions python3-rosdep python3-tk \
  ros-humble-moveit ros-humble-moveit-servo \
  ros-humble-moveit-task-constructor-capabilities ros-humble-moveit-task-constructor-visualization
sudo rosdep init; rosdep update

    Keep every ROS package on the same release. A half-upgraded system gives a MoveIt library mismatch when RViz loads the MTC panel:

    sudo apt update && sudo apt install --only-upgrade -y 'ros-humble-*'

    Gazebo is not used. Do not install ros-humble-gz-ros2-control; the workspace script skips it.

    Pass: source /opt/ros/humble/setup.bash && ros2 pkg prefix moveit_ros_move_group prints a path.

    Install uv

    uv creates the Python environments. It installs into your home directory and needs no sudo.

    curl -LsSf https://astral.sh/uv/install.sh | sh

    Pass: open a new terminal, then uv --version prints a version.

    Get the robot_remote code

    The repository is private. Ask its owner for access, log in with gh auth login, then clone it. Any location works. All later commands are run from inside this folder (they start with ./).

    gh repo clone Patrick-zhuyanxun/robot_remote ~/robot_remote
cd ~/robot_remote

    Pass: ls shows launcher quest_teleop recording setup dual_arm_sim …

    Install Isaac Sim 6.1

    Isaac Sim ships as one zip (about 9 GB). Unzip it to ~/isaac-sim-6.1. It brings its own Python 3.12 and its own copy of the ROS 2 Humble libraries, so it never uses /opt/ros.

    cd ~/Downloads && curl -L -C - --retry 5 -o isaac-sim-6.1.0.zip \
  https://downloads.isaacsim.nvidia.com/isaac-sim-standalone-6.1.0-linux-x86_64.zip
mkdir -p ~/isaac-sim-6.1 && unzip -q ~/Downloads/isaac-sim-6.1.0.zip -d ~/isaac-sim-6.1
cat ~/isaac-sim-6.1/VERSION

    Installed somewhere else? Put export ISAAC_SIM=/your/path in ~/.bashrc; every launcher reads it.

    The first start compiles shaders and can take several minutes. Later starts take 30–60 s.

    Pass: VERSION starts with 6.1.0.

    Build the ROS workspace

    Clones the igus ReBeL description and MoveIt config (fani8j/Igus_rebel, branch hcut-path-consistency, pinned commit) into igus_ws/src, applies our patch from igus_ws/patches/, installs apt dependencies with rosdep and runs colcon. About 5 minutes.

    ./setup/install_ros_ws.sh

    The patch sets open_loop_control: true in the simulated controller config. Without it, MoveIt-driven streaming in the sim creeps at about a third of the commanded speed.

    Add --with-irc to also build the older CommonplaceRobotics iRC_ROS packages; only the single-arm demos in igus_rebel_sim/ use them.

    Pass: the script ends with [ws] done and colcon reports no failed packages.

    Create the Quest teleop environment

    Creates .venv_quest: Python 3.10 so it can import the system ROS 2 rclpy, plus NVIDIA Isaac Teleop with the CloudXR runtime. At the end it asks you to accept the CloudXR licence (once per machine).

    ./setup/install_quest_env.sh

    Pass: the script ends with [quest] done.

    Create the recorder environment

    Creates .venv_record: Python 3.12 with LeRobot 0.5.1. Python 3.12 matches the rclpy bundled with Isaac Sim, which the recorder borrows.

    ./setup/install_record_env.sh

    Already have a LeRobot 0.5.x environment you train with? Skip this step and point the recorder at it, so datasets are written by the version that reads them:

    echo 'export LEROBOT_PY=$HOME/Robotic_infra/lerobot/.venv/bin/python' >> ~/.bashrc

    Pass: the script prints [record] lerobot + av OK.

    Network and ROS settings

    Firewall. If ufw is enabled, open the CloudXR ports for the Quest:

    sudo ufw allow 47998/udp && sudo ufw allow 48322/tcp && sudo ufw allow 49100/tcp

    Private ROS graph. Every launcher sources ros_env.sh, which sets ROS_DOMAIN_ID=42 and ROS_LOCALHOST_ONLY=1. Another machine on the lab network runs the same rig on domain 0; without this, commands from one PC move the other PC's arms. Use another domain with export ROBOT_REMOTE_DOMAIN_ID=43 if two people use this setup on one network.

    Datasets go to ~/datasets unless you choose another folder in the launcher or set ROBOT_REMOTE_DATASETS.

    Pass: sudo ufw status says inactive, or lists the three ports.

    Check everything

    One script checks every item above and says how to fix what is missing.

    ./setup/check_env.sh

    Pass: every line is OK and it ends with All good. Next: Set up the Quest.

    First time · Quest

    Set up and connect the Quest

    • Pair the headset with the Meta Horizon phone app and install all system updates. Old firmware has an outdated WebXR runtime.
    • Join the same Wi-Fi network as the workstation.
    • Use the controllers, not hand tracking. A stationary boundary is enough.
    • No developer mode and no app install: everything runs in the Quest Browser. Bookmark the client page below.

      Start the launcher first

      Press Start in the launcher and wait until the teleop dot turns amber (waiting for headset). The launcher shows the Server IP in large type. The workstation gets its address by DHCP, so it can change between days.

      Open the CloudXR client

      In the Quest Browser open:

      https://nvidia.github.io/IsaacTeleop/client/v1.3.131/

      Type the Server IP from the launcher into the server field.

      Accept the certificate

      Tap the accept cert link on the page. The browser warns that the connection is not private: choose Advanced → Proceed. Then go back to the client page. You need this again whenever the workstation's IP changes.

      Connect

      Press Connect and allow the immersive session. Hold both controllers in front of the headset. The teleop dot in the launcher turns green once both controllers are tracked.

      Stand facing the same way as the arms (recommended). If you face the robot, choose Facing the robot in the launcher before Start; hands and axes are mirrored for you.

      Every session

      Run a session

      Everything starts from one window: it launches the simulator, the Quest teleop and the recorder in order and shows their state. Run the command from the robot_remote folder.

      ./launcher/run_gui.sh

        Fill in the settings

        TargetIsaac Sim. Real robot is shown but disabled (reserved).
        ArmsLeft, right or both.
        CamerasHead, left wrist, right wrist. Fewer cameras make the simulation run faster.
        Resolution / FPSDefault 640×480 at 30 fps.
        TaskThe instruction stored with every frame, for example pick up the box.
        Dataset name, Save locationAn existing name appends episodes to that dataset; the window says which.
        StanceFacing the same way as the arms, or facing the robot.

        Settings are remembered for next time. The ? Manual button opens this page.

        Press Start

        Isaac Sim opens (30–60 s) and both arms move to the home pose. Then CloudXR and the recorder start. The run page shows a status dot per program: green when ready, amber while waiting, red when stopped.

        Connect the Quest

        Follow Set up the Quest → Every session. The teleop dot turns green when both controllers are tracked.

        Record episodes

        Press A or X to start an episode, do the task, press A/X again to save. Press B or Y to throw away a bad take. The launcher's Start / Save and Discard buttons do the same. The banner shows RECORDING, the elapsed sim time and the episode count.

        Stop all

        Stop all saves an open episode first, then shuts down every program. Logs of each program are in robot_remote/logs/ (Open log folder). Then check one episode.

        Every session

        Controller buttons

        The left controller drives the left arm, the right controller the right arm. Tap a button on the picture or in the list.

        Speeds are capped: 0.5 m/s, 90°/s rotation, 45°/s per joint (the ReBeL limit). Fast hand motions are followed smoothly with a short lag. Wrist pitch reaches about ±40° from the home pose before joint 5 hits its limit. Both arms freeze with a warning if they come within 12 cm of each other.

        Every session

        Record good data and check it

        • One episode is one attempt at the task, from A/X to A/X. Keep it short and complete. Discard failed attempts with B/Y instead of keeping them.
        • The recorder takes a frame every 1/30 s of simulation time. With three cameras Isaac runs at about 0.5× real time, so 10 s of your time is about 5 s of data.
        • An episode saves itself after 120 s of sim time.
        • Saving encodes the videos and takes a few seconds. Wait for the banner to show READY before the next take.

        Run from the robot_remote folder. Use the dataset name and Save location you set in the launcher for --name and --root; the dataset must already have at least one saved episode.

        The replay tool streams an episode's recorded actions back into Isaac and compares the result with the recorded states. Start Isaac on its own (no Quest teleop), then:

        ./dual_arm_sim/run_dual_arm_sim.sh --headless &
./recording/run_replay.sh --name dual_rebel_task --root ~/datasets --episode 0

        Healthy: mean error well under 1° and best-fit frame shift 0. Our reference run: mean 0.05°, max 1.7°, shift 0.

        Load it in Python like any LeRobot dataset:

        from lerobot.datasets.lerobot_dataset import LeRobotDataset
from pathlib import Path
ds = LeRobotDataset("local/dual_rebel_task", root=Path("~/datasets/dual_rebel_task").expanduser())

        • Teleop runs in .venv_quest (Python 3.10) so one process can use both isaacteleop and the system ROS 2 Humble rclpy.

        Troubleshooting

        No such file or directory when running a script
        The commands in this manual start with ./ and run from the robot_remote folder. cd into your clone first (for example cd ~/robot_remote), or put the full path in front.
        Replay says the dataset does not exist
        Pass the same name and Save location as in the launcher: --name <dataset name> --root <save location>. Record and save at least one episode first.
        The Quest page cannot connect
        Same Wi-Fi as the workstation? Server IP current (the launcher shows it)? Certificate accepted again after an IP change? Firewall ports open (Install → Network)?
        Teleop dot stays amber after Connect
        Enter the immersive session, switch both controllers on and hold them in front of the headset.
        The arm does not move when I hold grip
        Is that arm ticked in the launcher? Does the messages panel show engaged? Is start_right_arm_moveit.sh running? Stop it: its controller fights the teleop.
        Both arms freeze with a warning
        The inter-arm guard: the arms came within 12 cm. Move your hands apart, release and re-grip.
        Moving up makes the arm go down (axes mirrored)
        Check the Stance setting. Facing the robot mirrors the axes and swaps hands.
        Recorder shows "stale stream"
        A source stopped publishing. Check the status dots and the logs (Open log folder).
        Recording only has a few frames, or the time jumps
        A foreign /clock is mixing in. Every terminal must use ros_env.sh (domain 42, localhost only). The recorder warns when the clock jumps by more than 1 s.
        ros2 topic list shows nothing
        The terminal is on domain 0. Run source ./ros_env.sh first.
        RViz MTC panel error / MoveIt library mismatch
        ROS packages from two releases are mixed. Run sudo apt install --only-upgrade -y 'ros-humble-*', then rebuild with setup/install_ros_ws.sh.
        Isaac Sim starts but the arms never move
        Did Isaac start from a terminal with /opt/ros sourced? Use run_dual_arm_sim.sh in a fresh terminal. Run setup/check_env.sh.
        Isaac Sim takes minutes to open the first time
        It compiles shaders on first start. Later starts take 30–60 s.

        No match. Try a shorter word, or check the logs in robot_remote/logs/.
